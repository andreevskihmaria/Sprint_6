# UI-автотесты сервиса «Самокат»

Автотесты интерфейса учебного сервиса аренды самокатов [Яндекс Самокат](https://qa-scooter.praktikum-services.ru) — оформление заказа от начала до конца, раздел «Вопросы о важном» и переходы по логотипам. Selenium WebDriver, паттерн Page Object, отчёты Allure.

## О проекте

Проект по автоматизации UI-тестирования. Основной сценарий — сквозное оформление заказа самоката: заполнение двух форм, подтверждение и проверка модального окна об успешном заказе.

Ключевые решения:

- **Page Object Model.** Логика взаимодействия со страницами живёт в `pages/`, локаторы — в `locators.py`, тесты описывают только сценарий. Форма заказа состоит из двух шагов, и без разделения на слои тест на неё превратился бы в стену вызовов `find_element`.
- **Сквозной сценарий целиком, а не по кусочкам.** `test_order` проходит весь путь пользователя: главная страница → кнопка «Заказать» → первая форма → вторая форма → подтверждение → проверка успеха. Такой тест ловит проблемы на стыках шагов, которые не видны при проверке форм по отдельности.
- **Две точки входа в один сценарий.** Кнопка «Заказать» есть и в шапке, и в теле страницы. Тест параметризован так, что оба пути проверяются одним кодом с разными наборами пользовательских данных.
- **Раздел FAQ проверяется целиком.** Ожидаемые тексты всех восьми ответов лежат в словаре в `data.py`, тест параметризуется прямо по нему через `.items()`. Добавить девятый вопрос — значит добавить одну строку в данные, тест править не нужно.

## Что покрыто тестами

| Тест | Проверка | Кейсов |
|------|----------|--------|
| `test_order` | Полный цикл заказа самоката: обе формы заполняются, заказ подтверждается, появляется модальное окно об успехе | 2 — кнопка «Заказать» в шапке и в теле страницы, разные наборы данных |
| `test_question_answer` | При клике на вопрос раскрывается корректный текст ответа | 8 — все вопросы раздела «Вопросы о важном» |
| `test_logo_yandex` | Клик по логотипу «Яндекс» ведёт на главную страницу Дзена | 1 |
| `test_logo_scooter` | Клик по логотипу «Самокат» ведёт на главную страницу сервиса | 1 |

Итого **4 тестовые функции**, которые с учётом параметризации дают **12 тест-кейсов**.

## Структура проекта

```text
.
├── pages/                  # Page Object классы
│   ├── base_page.py        # Общие методы: клики, ожидания, скроллы
```

## Требования

- Python 3.10 или новее
- Установленный браузер Mozilla Firefox
- `geckodriver` в `PATH` — [страница загрузки](https://github.com/mozilla/geckodriver/releases)
- Для просмотра отчётов — [Allure CLI](https://allurereport.org/docs/install/)

## Установка и запуск

```bash
git clone https://github.com/andreevskihmaria/yandex-scooter-ui-tests.git
cd yandex-scooter-ui-tests
python -m venv venv
```

Активировать окружение — Windows:

```bash
venv\Scripts\activate
```

macOS и Linux:

```bash
source venv/bin/activate
```

Установить зависимости и запустить тесты:

```bash
pip install -r requirements.txt
pytest -v
```

Запуск одной группы тестов:

```bash
pytest tests/test_order.py -v
```

## Allure-отчёт

```bash
pytest --alluredir=allure-results
allure serve allure-results
```

Тесты размечены через `@allure.feature`, `@allure.title` и `@allure.description`. Заголовки подставляют параметры кейса, поэтому в отчёте видно, какая именно кнопка и какой набор данных проверялись.

## Результаты

Сквозной сценарий заказа проходит с обеих точек входа, все восемь ответов в разделе FAQ соответствуют ожидаемым, переходы по логотипам работают.

Наблюдения по ходу работы:

- **Форма заказа состоит из двух шагов, и переход между ними асинхронный.** Заполнение второй формы сразу после клика по «Далее» приводило к падению — элементы ещё не отрисованы. Решено отдельным ожиданием `wait_for_socond_form` перед работой со вторым шагом.
- **Раздел FAQ находится за пределами первого экрана.** До элементов нужно доскроллить, иначе клик не срабатывает. Скролл вынесен в метод страницы `scroll_to_faq`, а не продублирован в тесте.
- **Проверка текста ответа надёжнее проверки факта раскрытия.** Аккордеон может визуально раскрыться, но показать текст не того вопроса. Поэтому тест сверяет содержимое, а не состояние элемента.

## Что можно улучшить

- **Тесты запускаются только в Firefox** — фикстура жёстко создаёт `webdriver.Firefox()`. Кросс-браузерность решается параметризацией фикстуры, как это сделано в проекте [stellar-burgers-ui-tests](https://github.com/andreevskihmaria/stellar-burgers-ui-tests).
- **Драйвер нужно устанавливать вручную.** Переход на `webdriver-manager` убрал бы требование держать `geckodriver` в `PATH`.
